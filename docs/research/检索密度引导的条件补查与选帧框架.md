# 检索密度引导的条件补查与选帧框架

首版讨论：2026-09-18；设计定稿：2026-09-20。版本：**v1.0（六环节初版设计）**。本文是新框架设计的唯一维护入口，已按环节整合确认过程中的核心思想、理由和例子；临时评审稿不再保留。设计规则与实验效果区分，实施和测试见[本轮执行协议](../experiments/video_mme_50/2026-09-20/retrieval_density_v1/执行协议.md)。

## 一、研究目标与当前决定

先聚焦“由问题中的已知对象/场景找到入口，再到附近寻找线索”的问题，缓解粗采样漏帧、低分邻帧落选及重复画面占用预算。目标是提高同预算总体表现或一类问题的表现，不要求首版解决所有题型；效果须由后续统一条件测试验证。

核心思想：**少量高分锚点保住定位基础；新旧候选共同竞争补充名额；用视觉差异增加不同状态的保留机会；原种子的短间隔聚集支持提供预算倾向，剩余内容差异决定是否继续投入。**

| 项目 | v1.0固定规则 |
|---|---|
| 粗候选 | 全片1 FPS，目标网格0.25+k秒，映射到不早于目标的第一张源帧并去重 |
| 定位与特征 | 原问题BLIP ITM正匹配分数；同次前向取得纯视觉CLS并L2归一化 |
| 模型口径 | Salesforce/blip-itm-base-coco，FP32，batch上限16，官方384预处理，文本不截断 |
| 原定位种子 | 配置上限M=16，实际数量M_eff=min(M,N)，N为唯一粗候选数；不先做时间NMS/视觉去重 |
| 核心连接 | 相邻种子的粗采样目标时间间隔≤2秒 |
| 区域形成 | 每个核心按首末种子真实时间前后各扩4秒，裁剪后合并重叠/共享端点的窗口 |
| 条件补查 | 最终区域内至少一个原核心含≥3个种子；对获准最终区域完整补到2 FPS，仅一轮 |
| 细网格 | 全局0.25+0.5k秒；只处理新增目标，源帧去重，不再扩窗，不另加数量截断 |
| 锚点保护 | 每个最终区域保护一张最高分原种子，计入总预算 |
| 新帧处理 | 第6步提取同规格纯视觉特征；不新增问题ITM评分 |
| 区域内提议 | 与本区域全部已选帧比较，提出最大补充差异度候选 |
| 跨区域竞争 | P_R=(1+m_R−c_R)d_R；名额逐帧竞争，不预分配额 |
| 最终预算 | K_max=16；候选充足取16张，不足全取，不重复源帧，不引入区域外帧补位 |

表中k为非负整数。M与K_max虽在当前版本同为16上限，仍为独立配置概念。均匀/Top-K、旧方法、B/C-local及R的代码与历史产物保持不变，不恢复已回退的局部VLM评分器。

## 二、观察依据与适用问题

| 代表题 | 已观察到的问题 | 对新框架的启发与限制 |
|---|---|---|

| 395-2：拿到红书后做什么 | 目标画面高分，邻近宣传册等线索低分；较远后果也可能需要联系 | 低ITM不应再次否决邻帧，但有限窗口仍可能不够 |
| 544-1：摩托车离开时出来几个人 | 门口可定位，人物身份及完整过程难区分 | 不同画面不等于不同的人；历史均匀组实际答对 |

这些是研究动机，不用于逐题调整参数或给选择器提供标准答案。题面操作、真实证据布局与检索分布不能等同；集中不证明LOCAL，分散不证明GLOBAL。

## 三、框架执行流程

1. **定位入口。** 用原问题BLIP在1 FPS候选中找到最多M个种子；定位分数不等于最终回答价值。
2. **描述聚集。** 保留种子的原始时间分布，先形成核心再扩窗合并；短间隔支持影响补查和预算倾向，不进行语义题型分类。
3. **补足候选。** 对满足条件的最终区域按2 FPS回原片补查；新帧与区域内原候选共同备选，不因来源获得优先权。
4. **联合保留。** 每区保护一张定位锚点，再以局部差异提议和跨区加权竞争形成实际配额；不提前锁死预算，也不把视觉差异称为证据充分性。

流程为：**粗候选 → 问题匹配 → 定位种子 → 最终区域 → 条件补查 → 联合预算与选帧 → 后续问答评价**。六环节是逻辑职责，不要求拆成六个服务或重复解码的六轮执行。

### 1．粗候选生成

**目的与边界：** 先为完整视频建立统一、可复算的候选基础，本步不判断问题相关性、不筛黑屏，也不决定最终保留哪些帧；输出源身份与时间元数据供后续定位和精确补查。

只读原视频，按1 FPS网格映射和去重，保存视频/流身份、源PTS/time_base、源帧号、候选ID和采样目标。低帧率导致多个目标命中同一源帧时，沿用现有协议保留首次命中的粗目标作为该候选的规范目标时间；后续映射记录不覆盖它。

所有区域边界使用相对视频起点的有理数时间：

$$
t_i=(\mathrm{PTS}_i-\mathrm{start\_pts})\,\mathrm{time\_base}
$$

源PTS用于身份与精确读取；不能把绝对source_seconds与相对视频时长混用。目标时刻与真实源时刻分别保存，浮点秒只用于展示，不按平均FPS推算帧号。空候选、非递增/缺失PTS或无法核实源身份属于输入异常，不伪造帧或静默回退。

### 2．原问题匹配与粗帧特征

**设计理由：** ITM分数负责提供问题相关入口，纯视觉特征负责后续比较画面；二者用途分开。匹配低的邻帧仍可能包含答案，不能把定位排名直接当最终保留次序；不同问题的绝对分数也不作统一证据置信度。

以原问题计算全部粗候选的ITM正匹配分数，保留完整分数及稳定排名，不引入选项、答案、查询改写或范围分类，不做全片分数拉伸。

在**同一次ITM前向**中取得纯视觉编码器的CLS并L2归一化，供第6步复用，不为粗帧再运行一次视觉编码。评分按FP32、官方384预处理和batch上限16执行，末批可少于16；文本显式不截断。

第1、2步可以流式衔接：解码批次消费后释放RGB，仅保留可追溯元数据、分数及紧凑特征，不常驻整条视频的原分辨率候选。ITM不是图像余弦相似度，也不是答对概率。

### 3．定位种子

M表示定位种子数的配置上限，初版设M=16；实际种子数为M_eff=min(M,N)，不覆盖配置值M。按原ITM分数降序、源PTS升序、候选ID升序，取前M_eff个唯一粗候选。保留原始聚集信息，不先进行时间抑制或视觉去重。

**设计理由：** 本步要观察检索结果本来是集中还是分散。提前强制分散会抹掉密集支持，影响后续核心构建、补查和预算倾向；因此先保留分布，冗余处理留给第6步。种子上限M控制定位入口，最终上限K_max控制回答成本，两者同为16不表示每个种子都占一个保留名额。

完整粗候选和分数仍用于追踪；第6步的备选集合仅包含第4步最终区域内的候选，不因完整列表还在就自动加入区域外保底。种子不全部受保护，只有第6步确定的每区最高分种子必留。

### 4．构建最终区域

**设计理由：** 先用种子间隔形成核心，保留真实的检索聚集关系；再扩窗合并，确定实际取证范围。窗口相连不代表原种子本来密集，核心也不代表语义事件。预算尚未产生，最终区域确定后才进入补查和选帧。

1. 将种子按时间排序，相邻**粗采样目标**间隔≤2秒连成一个核心；孤立种子自成核心。
2. 对每个核心e，仅按首末种子的**真实相对源时间**扩窗一次：
   $$
   W_e=[\max(0,t_e^{first}-4),\ \min(T,t_e^{last}+4)]
   $$
   T采用视频流时钟下的有效时长，端点包含。
3. 合并重叠或共享端点的窗口，直到得到互不重叠的最终区域；不再次扩窗或按预算拆分。
4. 关联区域内粗候选、种子及父核心，冻结区域描述后进入第5步。

连接用目标时间、取证用真实源时间，是为了避免名义2秒因源帧映射变成2.002秒而意外断开，同时仍读取正确的源帧。改变扩窗半径不会重划原核心，但可能改变最终区域的合并关系；因此保留父核心成员，而不只保存合并后的种子总数。

**生产决策只需要：** 区域边界、候选/种子ID、父核心及各核心种子数。由这些记录一次性派生m_R（种子数）、c_R（核心数）和最大核心种子数即可；不维护另一套内部核心配额。

每区最高分锚点直接沿用第3步的原排名，不另造区域评分器；其他诊断统计按需由原始记录离线派生，不参与选择公式。

### 5．条件补查

最终区域内至少一个原核心含≥3个种子才获准。例如[3,1]触发，[2,2]与[1,1,1]不触发；不额外叠加绝对分数或质量阈值。

**设计理由：** 用连续检索支持决定哪里值得增加时间分辨率，而不是把扩窗合并后的数量冒充密集。三个种子是初版操作门槛，不是存在答案的统计证明。补查只扩大候选机会：未补查区域仍能从粗候选选多帧，已补查区域也不保证获得更多最终名额。

对获准的**完整最终区域**补到2 FPS：使用全局0.25+0.5k秒网格，主要新增0.75+k秒目标。原1 FPS候选完整保留；不再扩窗、不给新帧加分、不按未来预算反向决定补查。混合区域中的孤立核心附近及连接部分也会密采，这是已确认的范围选择。

统一相位让原1 FPS网格成为细网格的子集，避免窗口起点改变采样位置。约10秒窗口对应约20个细目标，其中约10个原目标、约10个新增目标，不是另外再补20帧；实际唯一帧数受边界和源帧率影响。

取不早于新增目标的第一张源帧，核对真实PTS与区域边界，再按源身份与全片已知粗候选、新候选去重。映射到旧帧时复用其ID，不创建第二份，也不覆盖旧采样目标；新增ID按源时间/源帧号稳定生成，不依赖并行返回顺序。映射越界、视频尾无可用源帧等正常边界丢弃需记录，与解码错误区分。

本步完成真实读取、合并、排序及画面可读取性，不只生成占位清单。补查仅一轮，不改变原种子/核心/区域统计；新增量由范围与2 FPS自然决定，不另设截断规则。资源不可接受时暂停，不静默降低FPS、缩窗或漏处理区域。

本步不做新帧ITM、视觉特征或选帧计算；用有界批次或临时资产将画面交给第6步，接口拆分不要求新帧重复解码。最终候选池冻结后才开始选择。

该边界保证补查模块独立：第5步回答“把哪些画面采回来”，第6步回答“怎样比较并留下哪些”。后续更换选帧规则时，可以复用同一补查候选池，而不必重新定位或补查。

### 6．联合预算分配与选帧

**准备表征。** 旧帧复用第2步特征；只对新增唯一源帧提取同模型、同预处理、同精度的纯视觉CLS并归一化。两条特征提取路径需用同一画面对齐，不能只检查维度；无效或非有限特征报错。不计算新帧ITM，其字段保持“未计算”，不当作0分。新增视觉计算属于真实模型成本。

**保护锚点。** 每个最终区域从原种子中保护最高分一张，计入总预算，不在后续竞争中移除。其他种子仍可竞争。保护单位是最终区域，不是每个内部核心。

保护少量锚点提供最低定位保证，同时为低分邻帧留出预算；保护全部原定位种子会在M_eff=16时耗尽名额。一张锚点不代表覆盖了合并区域内的全部事件，高分也不保证画面有效；这是初版的保守保留规则，而非证据认证。

**区域内提议。** 记C_R为该区域的唯一新旧候选，S_R为已选集合，初始只含保护锚点。定义：

$$
s(i,j)=\operatorname{clip}(\cos(f_i,f_j),0,1),\quad
\rho_i=\max_{j\in S_R}s(i,j),\quad
u_i=1-\rho_i
$$

每区提出尚未入选且u_i最大的候选x_R，令d_R=u_{x_R}。与全部同区域已选帧比较，而非只与最初锚点比较；不跨区域去重。同分按真实源PTS、候选ID升序。此规则确实偏向较大视觉差异，不声称已能区分有用状态与无关离群画面。

采用**最大相似度而非平均相似度**，是因为只要已有一张近乎相同的画面，就应降低重复加入的优先级，不能被其他不相似参照稀释。每次入选后更新参照：若B、C都不同于锚点H，但彼此很像，B入选后C应降权，而不是沿用第一次的差异排名。相似只降低优先级，不通过硬阈值删除候选；新旧来源不参与打分。

实现时维护每候选的ρ_i，新帧x入选后仅在该区域更新`ρ_i←max(ρ_i,s(i,x))`，无需全片两两相似矩阵或全量重算。已选集合增长时，区域最大补充差异度不会上升，但不保证每轮严格下降。

**跨区域竞争。** 权重只由原始种子关系决定：

$$
w_R=1+m_R-c_R,\qquad P_R=w_Rd_R
$$

每个含m个种子的核心有m−1个相邻连接，对所有核心求和即得m_R−c_R；“1”给予基本竞争权重，不是额外名额。[3]、[2,2]、[3,1]的权重均为3，[1,1,1]为1。这是短间隔支持量，不是精细时间密度，也不是独立证据数量。补查门槛与竞争权重职责不同，触发补查本身不额外加权。

采用**乘法而非加法**，使聚集支持不能单独制造补充价值：d_R=0时，再密集也不能获得正优先级；同等差异下密集区域优先，同等权重下差异更大的候选优先。已选内容增加后的重复反馈通过d_R更新，不再仅因为某区已选了几帧就额外扣分。

**简例（非实验结果）：** A/B/C权重为12/3/1，当前差异度为0.02/0.12/0.30，优先级就是0.24/0.36/0.30，先选B。若B更新后的差异度降至0.06，其优先级变为0.18，下一轮C优先。密集区域获得倾向，但不固定承包名额，孤立位置仍有补充机会。

每轮选P_R最大的区域，将其提议加入S_R，只更新该区域再竞争；全局同分仍按提议帧源PTS、候选ID升序。不再乘种子占比、峰值/平均分、补查后候选数或长度，不加平方根/对数、每区上限、1/(1+n_R)等修正。

因为w_R在同一区域内是正的常量，两层提议等价于在全部未选候选中取w_Ru_i最大者；保留区域接口是为了解耦和追踪，不再进行另一轮重排或配额平衡。

**总预算与输出。** C为所有最终区域候选的唯一并集，取K_eff=min(16,|C|)。候选耗尽的区域退出；若保护帧已达目标直接完成。优先级全部为0时仍按确定性同分规则补齐并标记“零差异补齐”，不另设提前停止阈值。最终保留所有保护锚点、源帧唯一且按真实时间排序；区域配额是实际入选数量，不是按权重比例取整。

当前M=K_max=16，有“区域数≤M_eff≤K_eff”，保护名额不会超预算；若未来改变M/K_max配置须重新校验，不能偷偷删锚点。16个种子形成16个最终区域时自然返回原Top-K16；其他情形不宣称严格退化为Top-K或均匀采样。

输出保留锚点、区域权重、逐轮提议/优先级、最相似参照及实际配额；候选资产保存一次，轨迹引用ID。实际输入帧数与视觉Token如实记录，不把候选不足时的输入量视为固定16帧。

## 四、实现、验证与版本关系
