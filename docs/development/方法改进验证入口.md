本轮协议见[执行协议](../experiments/video_mme_50/2026-09-15/method_followups/执行协议.md)。旧A/B/C/D入口保持不变。

| 路径 | 职责 |
|---|---|
| `src/videoqa_methods/improvements.py` | `reselect_local`、`select_clocal`、查询原词校验和单次生成、历史上游核验 |
| `src/videoqa_methods/followups.py` | 调用账本、工作进程、GPU调度、冻结身份、代理分母和无模型重放 |
| `src/videoqa_methods/followups_report.py` | E准确率/配对区间与Q事实代理统计 |
| `scripts/run_method_followups.py` | `--phase clocal/query/all`、`--resume`、`--replay-only`入口 |

| `scripts/render_followup_cases.py` | 原PTS源帧、官方384图板和点击查看页 |
| `tests/test_method_followups.py` | 窗口/配额/去重/查询约束/持久化恢复/配置隔离测试 |

## 从哪里开始读

1. 想修改局部选择：读`reselect_local`，它只接受候选池、特征、配置，不接收答案。
2. 想追踪上游一致性：读`select_clocal`与`compare_upstream`，正常路径独立扫描原视频。
3. 想检查查询约束：读`validate_query`及冻结`WHITELIST`；词汇通过不保证关系忠实。
4. 想恢复运行：先看`calls/<kind>/<qid>.json`，再读`CallLedger.invoke`。只有`completed`可以复用，其余禁止再次生成。
5. 想复算结果：读`proxy_manifest.json`和`Q_facts.csv`，再从`fact_metrics`进入。事实分母不随新输出扩展。

## 输出结构

```text
outputs/methods/<run_id>/
  protocol.json / method_config.json / code_snapshot/
  proxy_manifest.json / replay/
  calls/{scope,answer,query}/
  selection_checkpoints/ / features/
  results/{E,Q}/ / queries/ / query_freeze.json
  workers/ / blip_calls/ / failures/ / writes/
  status.json / events.jsonl / execution_*.json
  summary.json / answers.csv / Q_*.csv / E_*.csv
  cases/ / index.html / statistics.md
```

`selection_checkpoints`在最终QA前保存，属于必要运行开销，纳入E直接墙钟。答案完整返回落盘在解析结束后，另报。部分恢复的耗时单列，不放入首次处理性能均值。历史C的输入/模型协议相同，但批次、并发资源和日志机制不同，不能从小幅时延差推断算法提速。

查询阶段即使全部回退原题也必须保留50条生成记录；相同BLIP编码只跳过重新评分，不重新生成更有利查询。分析收尾脚本不负责人工语义review和最终建议；这两项需如实记录，不把自动统计视作完整人工审核。
