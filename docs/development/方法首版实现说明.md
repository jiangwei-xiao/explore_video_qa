# SB系列首轮实现说明

> 命名维护（2026-09-22）：现行统一名称见登记表；SB旧组别A/B/C/D/E、RB旧称R、RD旧称v1/soft/P1/D1/E1按所属阶段映射，不将答案字母作方法名替换。见[方法版本登记](../research/方法版本登记表.md)。

SB-1.0/SB-1.1/SB-1.2及SB-1.2-diag01的历史实现遵循[首轮协议](../experiments/video_mme_50/2026-09-14/method_v1/执行协议.md)。旧 `videoqa_runtime` 包和基线运行指纹保持不变，方法位于 `src/videoqa_methods/`。下文A/B/C/D为历史内部字段，不改名以保持复现兼容。

## 复盘入口

| 模块 | 主要接口 | 阅读重点 |
|---|---|---|
| `model_ops.py` | `ScopeClassifier.classify`、`FeatureScorer.score_batch_features` | 原问题纯文本分类；同次BLIP前向取得ITM与纯视觉CLS；共享生成参数不变 |
| `algorithm.py` | `segment_scores`、`compete`、`hotspot_candidates`、`reselect` | 分段、原公式逐帧竞争、未覆盖度及固定配额重选 |
| `refinement.py` | `fine_targets`、`decode_hotspots` | 四分之一秒网格、真实PTS锚点与绝对源帧号、两级新增上限 |
| `pipeline.py` | `scan`、`select_method`、`select_diagnostic` | A/B/C独立全片处理；C候选池生成时刻；D的诊断增量 |
| `worker.py` | `worker_main`、`loop` | 每卡模型常驻、分类/问答状态、计时前后落盘边界 |
| `run.py` | `execute` | 执行指纹、GPU归属、前5题门槛、剩余任务和恢复保护 |
| `records.py` | `validate_result`、`validate_group`、`check_recovery` | 16帧/配额约束、C/D关系、历史分数对齐、不重复已完成调用 |
| `report.py`、`visualize.py` | `summarize`、`render_cases` | 六组统计、机制代理指标、固定案例规则与可视化；均不调用模型 |

配置入口为仓库 `configs/method_v1.json`。该文件记录当前固定首版参数，不意味着任意修改字段都已通过协议验收；新参数版本应建立独立运行并补充相应测试。

## 数据流与结果解释

1. A固定λ；B/C先分类。选择器接口只接收视频和原问题，选项与标准答案不进入选帧计算。
2. RGB候选按批次进入BLIP，返回逐帧相关性和768维归一化纯视觉CLS。候选、分数、特征行号一一对应。
3. 初始分段固定，16次竞争记录每段提名、全局获胜帧、相关性、代表分数、重复度及配额状态。
4. C记录全部热点的通过／跳过原因。补查从粗PTS锚点恢复真实源帧号，新增候选按时间排序后编号为N、N+1……；原候选不重编号。
5. C保存生成候选池前缀的直接耗时，再进行段内重选与最终问答。D只使用这份已冻结候选池；D归因成本等于C前序实际成本加D新增操作，不包含C最终回答。
6. 每个A/B/C结果保存对应特征文件。D引用C的特征与结果哈希，不伪装成独立采集的数据。标准答案只在最终输出产生后用于计分。

`pool`包含初始数量、完整候选/分数、分段、小波信号、逐步竞争、配额、热点、局部解码和最终选择。`scope_state`、`answer_state`区分已开始/已返回的模型调用；`timings`和`timing_kind`区分直接测量与诊断归因。长视频最多保留一个RGB批次及CPU特征矩阵，不缓存全部原分辨率视频帧。

## 准备、运行与审计

在项目根目录执行，使用专用Conda环境：

```bash
conda activate explore_video_qa
bash scripts/setup_methods.sh
CUDA_VISIBLE_DEVICES=0 VIDEOQA_GPU_TESTS=1 OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 \
  python -m pytest -q tests/test_methods.py -k blip_scores_match
```

方法依赖的版本约束和锁文件单独维护。原基线锁含Conda构建机路径，因此方法安装使用纯版本约束；不改写旧基线锁。现有基础环境必须先就绪。

后台运行示例使用新的运行编号；执行前确认本轮已经获准，不重复已完成的实验：

```bash
mkdir -p outputs/methods
nohup setsid /App/conda/envs/explore_video_qa/bin/python -u scripts/run_method_experiments.py \
  --run-id method_v1_next --gpus 0,1,2,3,4,5,6,7 \
  > outputs/methods/method_v1_next.launcher.log 2>&1 < /dev/null &
```

状态在运行目录的 `status.json`，日志在外部launcher文件及内部 `logs/`。同编号恢复使用 `--resume`；执行代码、依赖锁及参数必须一致。不确定生成或尚未恢复的已完成分类会停止，不能靠重新答题掩盖状态缺失。

完整结果到齐后自动统计和渲染预测变化案例；执行代码与事后分析代码分别记录快照。事后审计命令：

```bash
python scripts/audit_method_results.py outputs/methods/method_v1_next
```

审计会重放分段、预算竞争和固定配额重选，检查全部问答/分类提示词、特征和调用数，不运行新模型调用。优化建议单独输出，首轮结果冻结后不自动调参或追加版本。
