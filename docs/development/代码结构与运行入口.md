# 代码结构与运行入口

所有命令在远端项目根目录 `/home/admin/projects/explore_video_qa` 执行，使用专用Conda环境 `explore_video_qa`。环境重建见[环境说明](../setup/LLaVA推理与环境.md)，实验条件见[实验索引](../experiments/README.md)。

## 实现分工

代码保留在 `src/`、命令保留在 `scripts/`、测试保留在 `tests/`。现有Python模块与CLI路径是已验证接口，也被基线实验指纹引用，因此本次文档分类不改变这些路径。

| 职责 | 实现 |
|---|---|
| 官方LLaVA加载、合成预热、16帧问答和Token检查 | [llava_backend.py](../../src/videoqa_runtime/llava_backend.py) |
| 源PTS与均匀采样、精确选中帧解码 | [video.py](../../src/videoqa_runtime/video.py) |
| 流式候选、BLIP评分、Top-K选择及分阶段计时 | [baseline_selection.py](../../src/videoqa_runtime/baseline_selection.py) |
| 运行指纹、GPU分配、试跑门槛与主调度 | [baseline_run.py](../../src/videoqa_runtime/baseline_run.py) |
| 每卡长期进程、逐题执行与尝试记录 | [baseline_worker.py](../../src/videoqa_runtime/baseline_worker.py) |
| 结果核验、候选配对与恢复规则 | [baseline_records.py](../../src/videoqa_runtime/baseline_records.py) |
| 准确率、配对区间、耗时分位数和报告 | [baseline_report.py](../../src/videoqa_runtime/baseline_report.py) |
| 问答提示词、选项格式与答案解析 | [protocol.py](../../src/videoqa_runtime/protocol.py) |
| 项目路径、哈希、原子JSON写入与离线配置 | [common.py](../../src/videoqa_runtime/common.py) |

`configs/`区分机器生成的源码／模型身份及环境记录、研究方法参数（如`retrieval_density_v1.json`）和冻结版本登记（`releases/`）。机器身份记录不手改，已测参数变化另建版本。每次基线的实际条件由入口冻结到 `outputs/baselines/<run_id>/protocol.json`；样本名单固定在 `data/manifests/`。根目录的环境定义与锁文件供准备脚本使用。

## 命令入口

| 命令 | 用途 |
|---|---|
| `bash scripts/setup_llava.sh` | 建立Conda环境、安装固定依赖和官方源码、核验本地权重 |
| `python scripts/prepare_runtime.py` | 重新核验并生成本机资产记录和SigLIP缓存；会更新本机记录，不对已完成运行随意执行 |
| `python scripts/run_llava_smoke.py --help` | 单个冻结开发题的输入与运行验收 |
| `python scripts/run_baselines.py --help` | 均匀／Top-K开发50题，两组、16帧默认协议 |
| `python scripts/summarize_baselines.py <运行目录>` | 从已保存的100条结果重建统计，不重新生成答案 |
| `python scripts/capture_runtime_acceptance.py` | 记录最初单题验收和环境锁，非批量基线入口 |

```bash
source /App/conda/etc/profile.d/conda.sh
conda activate explore_video_qa
cd /home/admin/projects/explore_video_qa
python -m pytest -q
```

以下后台示例使用新运行编号；执行前确认确实需要新测100条，以及指定GPU空闲。运行编号已存在时必须另选新编号或按恢复规则处理。

```bash
mkdir -p outputs/baselines
nohup setsid /App/conda/envs/explore_video_qa/bin/python -u scripts/run_baselines.py \
  --run-id videomme50_uniform_topk_next --gpus 0,1,2,3,4,5,6,7 \
  > outputs/baselines/videomme50_uniform_topk_next.launcher.log 2>&1 < /dev/null &
```

状态在 `outputs/baselines/<run_id>/status.json`，日志在 `<run_id>.launcher.log` 与运行目录的 `logs/`。终端或VSCode断线不停止已脱离会话的进程。

恢复同一轮时在原命令增加 `--resume`。恢复要求代码、环境锁、模型身份及协议未改变，成功结果直接跳过；不确定生成状态暂停核查。不要为通过指纹检查而修改历史协议或结果。后续改变实验设置时，建立新运行并按明确计划执行。

## 产物分层

- `docs/experiments/<数据集>/<日期>/`：维护可读协议与结果解释，供review和论文写作。
- `outputs/baselines/<run_id>/`：保存原始逐题JSON、分数与源帧、调用记录、日志、统计和冻结代码快照；历史文件原样保留。
- `data/manifests/`：冻结开发／预留／替补名单及审计；视频与压缩包保留在 `data/videos/`、`data/archives/`。
- `docs/related_work/analysis/`和`pdfs/`：论文解析与原文，来源及PDF哈希记录在 `pdfs/sources.json`。

原始实验产物、视频、缓存和论文PDF遵循Git忽略规则。新代码与文档每次提交前review确认，不自动提交或推送。

## R区域边界实验入口（保留对照，非默认方法）

`src/videoqa_methods/region_context.py`提供替换计划与精确邻域选择，`region_run.py`隔离离线门槛、正式调度和调用账本；`tests/test_region_context.py`覆盖保护、同分、短池、VFR及恢复。保留理由是复算已完成实验及后续单因素对照，不代表R取得准确率提升，也不将此运行器升级为通用公共层。

```bash
/App/conda/envs/explore_video_qa/bin/python scripts/run_region_context.py --help
/App/conda/envs/explore_video_qa/bin/python scripts/summarize_region_context.py --help
```

入口支持`--phase offline`与`--phase formal --resume`；正式阶段必须已有绑定运行指纹的通过门槛。这里只查询帮助，不自动重新运行已完成50题。统计入口会重建指定运行的派生统计文件，冻结结果不为文档整理重新生成。需要复现时先查[R协议](../experiments/video_mme_50/2026-09-17/region_boundary_v1/执行协议.md)，使用明确授权的运行编号与预算，不修改历史指纹绕过恢复检查。

| 范围 | 入口 | 性质 |

| P1/D1/E1离线归因 | `analyze_priority_decoupling.py`、`analyze_density_reward_decay.py`、`analyze_local_distance_scale.py` | 复用冻结特征，不新增问答 |
| 区域有效性与人工入口修复 | `analyze_region_validity.py`、`prepare_entry_repair_review.py`、`run_entry_repair_diagnostic.py` | 只读盘点/定向粗选，不是自动检测器 |
| 推广资格能力探针 | `prepare_promotion_probe.py`、`run_promotion_probe.py` | 64次辅助分类，不是原题问答，未接入RD-2P |

后两类及RD-2P的独立实现暂保留在`src/videoqa_audit/`，不因目录名称推断是否调用模型；以各轮协议、调用账本和注册版本为准。本次归档不迁移已被实验指纹引用的路径，也不格式化已测代码。结果/特征/人工标记及其快照在4090仓库`outputs/`，不是Git克隆自带资产；缺失时停止核验，不能修改历史哈希绕过。

全量执行需独立确认题集、调用/复用口径、短池实际帧数、按视频成簇的统计及后台恢复；不要通过替换200题清单直接启动现有E1入口。当前统一结论见[RD-2P实验记录](../experiments/video_mme_200/2026-09-22/density_e1/实验记录.md)，入口优化边界见[推广能力探针](../experiments/video_mme_200/2026-09-22/promotion_probe/验证记录.md)。
