# 单帧可见事实描述诊断

现有Qwen能明确描述滑板、公交车、玫瑰和船等对象，但固定简短描述遗漏了取枪关系和图中等号表达。因此不将通用图像描述直接作为完整证据，不接入正式选帧，不继续调提示词。

## 固定范围与成本

使用原Qwen2.5-VL-7B、BF16、FA2，对三个视频六张已有源帧生成一次简短可见事实描述。输入不含原问题、答案选项、标准答案或有利／不利标签；固定英文指令要求只描述可见对象、动作、空间关系和清晰短文字，不推断动机、未见事件或人物姓名。单图官方预处理，贪心最多96新Token；这是辅助单图协议，不冒充正式视频32帧QA。

本轮6次真实辅助描述生成、1次合成描述、0次数据集新答案。不是“无模型调用”，也不和既有18次置信分布前向或旧16次诊断混算。北京时间2026-10-03 22:29完成，后台PID/SID 1445900；六份调用恢复内容哈希不变，新增生成0。源PTS、源帧号、RGB哈希、处理器Token／像素及完整原文保存在`outputs/diagnostics/visible_facts6_20261003_r1/`，入口`scripts/probe_visible_facts.py`。

## 画面与输出核查

| 题目与候选 | 描述内容摘要 | 初审边界 |
|---|---|---|
| 409-3，80 | 皮夹克人物拿着红玫瑰与白色布状物，处于走廊 | 原文没有指出枪或盒子关系；源画面中包装展开、物体部分遮挡，不能仅凭单帧要求恢复完整取枪过程。既有人工修复同时加入77和80秒，不是单独80秒的因果验证 |
| 409-3，94 | 人物持枪瞄准，背景有饮料售卖机标志 | 提供持枪状态，不能回答此前枪藏在哪里 |
| 556-1，42 | 红鞋、浅色裤子、黑色滑板和地面 | 捕获滑板对象，但原文“站在滑板旁”没有准确表达踩踏或通勤过程，不能把对象识别等同完整动作关系 |
| 556-1，47 | 公交车、路口、建筑文字与前方车辆 | 区分了道路场景，但没有证明主人公乘坐公交车；背景文字未逐字作真实性认证，不直接用于检索 |
| 383-2，1118 | 金色柱状装置位于紫色船状物左侧 | 捕获船，遗漏等号和装置身份，不是完整量子计算机类比描述 |
| 383-2，1124 | 转录Simulating Nature、Encryption和问号 | 与船图不同，可作为功能文字画面的内容说明，不能替代船只类比 |

以上为事后有限审核，不是描述正确率样本。通用一句话描述可能压缩掉答题关键关系，单帧也未必包含足够的过程；不将描述缺失一概判成模型没有能力。未进行“描述→自动排名→选帧→QA”的验证，因此没有方法精度结论。

相关路线存在先例：[VideoTree官方说明](https://videotree2024.github.io/)使用关键帧描述支持后续LLM推理；仓库[A.I.R.解析](../../../../related_work/analysis/03_AIR_Adaptive_Iterative_Reasoning.md)也区分强模型分析与最终回答的成本。它们不能证明本轮Qwen描述足以支持我们的固定32帧选择，亦不属于同成本直接比较。

## 后续优先级
