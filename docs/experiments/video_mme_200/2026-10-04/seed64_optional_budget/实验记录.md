# 更大定位入口与可选区域预算预检

本阶段只检查结构，不新增模型调用或问答。当前exp12及其全量1710/2700结果保持不变，尚未构建M64完整候选池，也没有M64准确率。

## 为什么检查

此前M16/K32开发135/200低于M32/K32的138/200；等权混入均匀的exp22也没有净收益。这不证明更多种子必然有效，但提示应区分“更多问题相关的入口”和“强制给每个入口分配最终帧”。本轮仅检查M64/K32这一固定工作点，不搜索其他种子数、窗口或连接间隔。

## 全量几何核对

复用2700题原粗候选及原问题评分，先逐题重现M32的种子、核心合并、真实PTS扩窗和补查触发。全部与冻结方案一致。随后只将种子上限改为64，仍使用2秒核心连接、±4秒窗口及原合并规则。

| 指标 | 结果 |
|---|---:|
| 原区域总数 | 21069 |
| M64区域总数 | 30392 |
| M64单题最多区域 | 48 |
| 超过32个区域的全量题数 | 79（中1、长78） |
| 其中开发200题 | 7 |

开发集冲突题为638-1、736-2、753-3、755-1、809-3、870-1、896-3。原规则“每区至少一张锚点”在这些题中无法满足K32。因此不能直接改参数运行，不删题、不静默回退M32、不临时合并窗口来掩盖问题。

## 只放开配额下界的控制

在原M32全部冻结前缀与覆盖曲线上，将预算约束由`n_r≥1`改为`n_r≥0`，其他目标不变：最大化`Σ w_r C_r(n_r)`，总和仍为实际预算，`C_r(0)=0`。正配额区域仍从原锚点开始取前缀；零配额区域不消耗最终帧。这是新的可行域，不是新的证据分数。

全量原DP配额全部重现；放开下界后开发200题离散选择完全不变，全量仅625-3改变。该题配额从`[1,10,21]`变为`[0,31,1]`，代理目标增加约0.33398。它说明即使只放开一个约束，也可能引发大幅预算重排，不能称普遍温和或自动有益。该题未重新回答，不附用旧预测计算新准确率。

## 下一步边界

可以继续设计“更多候选区域、允许零配额、正配额才保护区域锚点”的完整候选，但不能把它包装成原exp12仅改种子数的成绩。先保持原窗口、2FPS补查、L×sqrt差异局部次序、原问题加权覆盖和密度权重不变，明确新增候选的来源及特征计算成本，再做模块与输入验收。

当前没有放行新问答。若后续形成完整版本，应独立登记、保持K32和Qwen协议，不扫描参数，不把几何覆盖增加或代理目标上升当作QA收益。
