# 问题条件状态表征先行验证

本轮检验可见状态是否能在原问题条件下被更合理地保留。此前同位文字变化能增加部分列表或采购约束，却也奖励计时器、片头和讲解字幕，丢失平躺动作状态。这里不修补该文字规则，不改变定位与预算，而是验证一个新的问题条件表征；没有预设它优于原视觉特征。

## 固定表示与接入方式

使用本地Qwen2.5-VL-7B冻结权重、原BF16与FA2环境。每张完整RGB独立作为单帧视频，时间patch只重复自身；保持像素100352–602112、官方chat template及编码FPS2。输入只有原问题，没有选项、答案、人工证据说明或生成式分类指令。

官方forward的最后语言层输出提供最后输入位置状态h。使用同问题、同尺寸、同视频grid的纯黑画面状态h0作为基线，固定定义：

`g_i = normalize(h_i − h0)`。

它表示画面相对空白对当前问题输入状态的影响，是待验证代理，不是答案证据概率或已证明的语义距离。不能从单帧状态自动推出“最后”“之后”等关系完整。零残差没有新信息方向，对涉及它的帧对沿用原视觉重复度，不增加空图奖励。

固定exp07候选、原问题BLIP支持L、区域、锚点及配额。只将D改为有效g之间的截断余弦最大值，仍使用`L×√(1−D)`。本轮不重算覆盖曲线或DP，不换层、池化、相似度指数或融合系数。

这与exp24只使用视觉网络post-merger均值不同：本轮明确运行语言网络prefill。只观察隐藏状态，不调用generate，不解码或使用logits选择帧。实际视觉和语言前向、预处理、显存、加载及落盘分开计费，不能称免费替换。模型媒体注入与MRoPE仍通过[固定Transformers官方实现](https://github.com/huggingface/transformers/blob/v4.50.0/src/transformers/models/qwen2_5_vl/modeling_qwen2_5_vl.py)，不修改安装源码。

## 银行与先行评价

固定八题007-2、022-1、035-2、584-3、191-3、538-1、103-1、383-2。银行由两配置的原种子、exp07输入、已结束文字版本的实际竞争帧及已列状态见证组成，最多768张唯一源帧。重复源帧通过真实帧号与PTS对应，图像身份在前向前冻结；人工见证只决定事后比较对象，不进入编码器或最终选择公式。

保持每题原实际竞争上下文：缺失状态与原末位胜者比较；已选状态在原入选时刻与预先冻结的下一竞争帧比较。原受保护锚点和只有一名额的单元单列，不能把无法替换归咎于新表示。584的582秒是同一平躺状态的另一见证，不能把它超过520秒自动算新增事实。

首阶段真实prefill数量在准备完成时冻结；另有8次空白基线和4次合成接口前向，最终QA0。合成检查同图同问题重复、横竖屏及改变问题确实影响状态，不将其当语义有效性验证。

进入全池试点准备需要至少两个独立视频中，原缺失状态相对实际竞争者的优先级改善，并且保护状态没有明确损失风险。再重算完整候选池、冻结新输入并查看状态保护，不能用银行排序代替实际最终选择。数值异常、输入身份不符或未知前向暂停；不修剪银行或增加逐题例外来通过门槛。

完整试点通过后才决定两配置开发200题，最多400次新最终问答，完全同输入可事前核验导入历史答案。两配置使用同一D规则；两者不低于exp07且Qwen至少140/200或LLaVA至少128/200，并有跨视频证据支持时，才考虑同版本全量。这是资源门槛，不是显著性保证，也不把反复使用的开发集称盲测。

## 执行与恢复

入口`scripts/probe_task_conditioned_state.py`，接口`src/videoqa_methods/task_conditioned_state.py`。先行任务在GPU7独立长期进程执行，CPU和解码各2线程；后续阶段重新检查空闲卡，再决定并行规模，不抢占其他进程。

后台采用nohup与setsid、关闭stdin、日志重定向及排他锁。模型前向前保存输入开始状态，返回即保存原FP32状态；未知开始不得重发，完成返回只恢复归一化及评价。完成恢复核对返回/特征哈希，不加载GPU或新增前向。原模型、选帧、答案、OCR及已冻结事实目录不改写。

本轮产物位于独立`outputs/diagnostics/question_state__pilot8__20261009_r1/`。当前只登记能力探针，不登记exp32正式执行，不附用旧答案作为新成绩。若先行失败，结束这套固定表示；若有正向线索，通过实际选择保护后自主决定开发及全量，不因八卡空闲强行扩测。
