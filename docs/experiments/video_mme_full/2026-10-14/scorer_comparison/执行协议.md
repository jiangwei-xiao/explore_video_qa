# BLIP评分器全量对照执行协议

日期：2026-10-14。运行：`scorer_comparison__blip2__qwen32_llava8__20261014_r1`。

本轮比较BLIP-1与BLIP-2检索前端在Qwen32、LLaVA8两个工作点的表现。四种方法为BASE-Uniform、BASE-BLIP-TopK、RD-1.2-exp07、RD-1.2-exp12；方法公式与问答协议不变，均匀不使用评分器。S1历史答案全部复用，S2最多新增六组×2700＝16200次最终问答，同题完整输入一致时共享或核验导入。

主实验同时更换ITM分数和纯视觉表征，不称为分数单因素验证。两工作点的开发200题另做S2分数＋S1特征的零问答诊断，缺失的新细帧仅补S1纯视觉前向，不新增S1 ITM。该诊断没有答题成绩。

## 选择和问答条件

1. 冻结Video-MME全2700题、900视频、原选项顺序；标准答案只供生成后计分。
2. 初始1 FPS、0.25秒相位、真实PTS映射和源帧去重，原问题全文评分，禁止截断与选项检索。
3. 新接口只提供K，种子数为min(K,粗候选数)；核心连接2秒、扩窗±4秒、原窗口合并；至少一个原核心含3种子时在原合并区域2 FPS补查。
4. 按S2分数重建种子、窗口和合法细池；新帧只有纯视觉特征，没有ITM分数。精确解码沿用冻结实现。
5. exp07/12共享池、锚点与局部前缀，分别以等权／原问题ITM加权粗参考覆盖执行原DP。预算上限K，不重复凑数。
6. Qwen32采用原官方视频输入、BF16＋FA2、像素100352–602112、编码FPS=2，奇数内部补末帧；LLaVA8采用384、qwen_1_5、BF16＋SDPA，满8帧1680视觉Token。
7. 两模型保持固定LMMs-Eval参考任务、无字幕音频和额外时间说明、贪心、batch1、种子2027、最多16新Token。不二次抽帧。

## 实施和恢复

独立入口`scripts/run_scorer_comparison_full.py`。按`controls → preflight → coarse → refine → mixed → prepare-qwen32 → qwen32 → prepare-llava8 → llava8 → report`推进。下载等待期间可先完成控制重放；完整准备阶段会核验已有控制来源再引用。

后台采用nohup、setsid、关闭stdin、日志重定向和排他锁。每阶段检查GPU0–7真实空闲状态，一卡长期进程、CPU和解码各2线程，阶段内不扩卡。真正断开SSH再连接验收独立存活，断线不重启。

检索前向只接收原问题，细帧不评分。局部暂存PNG在特征、池和完成检查点全部落盘后逐文件释放，保留RGB摘要及真实源身份；失败现场不删除。粗特征跨预算共用，补查视觉计算按预算分别记录。

正式输入冻结源帧、RGB、官方像素、完整提示Token、视频grid和模型/环境身份。历史输入一致时仅导入已完整返回且同生成协议的答案；同题方法一致时只生成一次，固定方法顺序指定主账本。导入/新调用划分在生成前冻结，答案正确性不参与划分。

固定先行题为001-1、001-2、001-3、002-1、002-2、133-1、134-1。合成先检查1/7/8/11/31/32帧等实际后端边界。先行以输入和执行正确性放行，不以正确率放行。其余按时长降序动态调度；同题三方法的新调用同卡、同进程。

生成前记账、返回即保存原文。答错与解析失败不重跑；已启动失败占额度。OOM、指纹或输入不符、生成状态不确定即暂停，不降精度、分辨率、帧数或正式批量。有完整原始返回时只恢复后处理；部分完成题沿用原物理GPU。
