## 准备、后台与失败控制

独立入口`scripts/run_adjacent_context_development.py`与薄适配读取旧资产。先验证源资产、模型/环境、代码和原离线完整性，再在各自环境以有界CPU进程精确解码、处理820份输入。195引用与625新调用完整发布后，才可开始首个真实生成。

每单元最多2张启动时实际空闲GPU，总计最多8张，不抢占。单元内每卡长期工作进程、CPU/解码各2线程；每实际工作进程一次同预算合成，最多8次。原始返回检查点、完整提示、真实输入摘要、Token、计时及显存逐条保存。

先处理每个单元冻结顺序前5题，引用题只核验；放行依据输入与执行正确性，不依据答案对错。其余新任务按视频时长降序分配到固定GPU。每题GPU、源身份和调用ID持久化，恢复不迁移已分配物理卡。

```bash
nohup setsid /App/conda/envs/explore_video_qa_lmms_qwen/bin/python -u \
  scripts/run_adjacent_context_development.py \
  --run-id rd12_exp33_development_20261016_r1 --stage all \
  > outputs/methods/rd12_exp33_development_20261016_r1.coordinator.log 2>&1 < /dev/null &
```

协调器使用完整评测环境；模型子进程自动切换对应冻结环境。关闭stdin、日志重定向、排他锁、PID/SID和心跳持久化，脱离Codex/VSCode/SSH自动执行输入准备、先行、主体、汇总和审计。观察断线不重启任务。

生成前记账，返回边界立即保存原文；已开始失败占625额度，答错及解析失败不重跑。OOM、输入/指纹不符或未知生成时全局暂停，只允许在途调用完成落盘，不自动新增工作进程或合成重试。完整返回可以只恢复后处理；原进程中断且仍有未执行任务时，先审计账本、物理卡和合成额度，不自动替换进程。本轮完成恢复必须0新增生成。
