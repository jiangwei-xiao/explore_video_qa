# 帧组事实提取能力诊断：结果与主线判断

日期：2026-10-16（北京时间）。运行：`evidence_observation__pilot12__20261016_r1`。对应[执行协议](执行协议.md)及[主线工作文档](../../../../research/RD主线收束与下一阶段推进.md)。

## 1．结论先行

**120次辅助生成和4次合成全部完成，但这套固定观察器没有通过能力门槛，不进入选择目标设计或新问答测试。** 最终QA、BLIP、补查及独立视觉特征调用均为0；未登记exp35，exp07/12及历史结果不变。

需要区分两个层面：

1. **固定输出协议失败。** 120份输出全部带Markdown代码围栏；冻结的“仅JSON”解析器全部判失败，四帧有效JSON为0/24，单帧为0/96。不改解析器、不重发生成，不把事后去围栏当作达标成绩。
2. **不仅是格式问题。** 单独只读查看围栏内文本后，仍发现错帧引用、纸币误识为信用卡、把提示中的时间写成屏幕文字，以及大量遗漏“当前画面不能确认全片限定”的情况。部分文字和物体确实能读出，但不足以成为可靠的、带来源的回答价值信号。

本轮否定的是**这套固定提示、视频输入、编号约定及输出接口的可直接使用性**，不是证明冻结Qwen永远不能提取事实，更不是证明所有帧组机制无效。

## 2．输入与执行验收

固定12题、24个不重叠四帧组、96个唯一真实源帧；每题见证组与exp12实际选择对照组均来自旧Qwen32合法池，没有根据本次输出选图。

- 96次独立单帧＋24次联合四帧，均已返回并保存原始文本/Token，120次正常EOS，截断0，运行期失败0，无重试。
- 事前可见事实、关系和限定已在首个模型调用前冻结。新标注不混入旧42题75事实目录；模型输出后未改写真值。
- 输入不含选项、标准答案、评价标签或历史对错；真实时间仅作为本诊断的辅助文本，不修改正式QA协议。
- Qwen使用原冻结环境、BF16＋FA2、官方视频输入、像素100352–602112、编码FPS2。每次实际只有一次视觉前向、一次prefill，帧序、RGB、像素及提示Token与CPU冻结身份一致，没有二次采样。
- 单帧内部重复自身为一个时间patch，不当作两张源证据；四帧为两个时间patch。**输入技术身份正确不等于模型能正确绑定外部帧编号。** 当前结果不能分离模板示例复制、时间patch与语言指令遵循各自的因果影响。
- 两张空闲GPU6/7、每卡长期进程；使用nohup＋setsid后台执行。关闭发起SSH会话后，重连见同一PID/SID、原工作进程及进度继续，无重启。
- 完成后CPU恢复检查新增真实/合成均0，原始生成与输入哈希不变。1071项测试通过、1项既有跳过；新增16项测试覆盖输入/引用、JSON、256Token配置隔离及不重复生成等边界。

准备阶段曾因旧来源索引不含视频路径而在0模型调用时停止；补齐既有冻结视频清单的身份读取后继续同一r1。没有重算候选、分数或特征。成功准备计时单列，首次失败准备未测量耗时，不计为免费恢复性能。

单帧调用沿用其在四帧组中的ID，例如只提供ID3时，输出仍常引用ID1和ID2；这不是多看到了一张画面。联合条件虽然没有越过1–4的编号范围，仍会把帧4文字说成帧1/2/3可见。因此“编号在合法集合内”只是语法检查，不是事实来源验收。

主协议规定无效JSON记失败：正式观察正确度、事实召回及适用限定通过数均按失败记0，不能据此把语义能力简单描述成0%。下节另给**不改变门槛的内容复核**。

## 4．24组内容初审与实际分母

事前标注及全部单帧/帧组文本的AI初审已完成；不是用户一致率，也不是独立盲审。自事前标注开始至审查记录落盘的墙钟上界为18.58分钟，包含等待和运行，未超过90分钟。未确认的陈述不计正确。

下表只为区分格式和内容：人工读取一层完整围栏内的原文字，不补键、不重映射编号、不修改原解析结果。完整观察句的真伪和其中已列原子事实的召回分别核对，前者有错误并不抹掉句中另一个真实原子事实。

| 补充内容指标（不作通过成绩） | 结果 |
|---|---:|
| 按引用画面支持的完整观察 | 14/43；另7项不确定、22项不支持 |
| 逐帧组观察正确度宏平均 | 40.63%（24组） |
| 按引用画面支持的关系陈述 | 5/17；另5项不确定、7项不支持 |
| 已列可见事实宏平均召回，要求来源绑定正确 | 42.86%（21组） |
| 忽略错帧、只看组内文字是否说出正确事实 | 47.62%（21组；不可用于来源可靠性） |
| 四次单帧文字并集的同口径召回 | 75.40%（21组；同样忽略坏引用） |
| 限定范围判断正确 | 4/22；2组不适用单列 |
| 明确联合增量的独立视频 | 0/12，未达到至少3个且含MLVU的门槛 |

没有已列可见事实的三个对照组为103-1、113-3、584-3：它们仍进入观察和限定评价，不给事实召回满分，也不把“没有已列事实”解释为画面完全无信息。

单帧并集用了4次调用、更多输出Token，且上表文字口径忽略了坏引用；因此75.40%对47.62%只是本诊断的描述，**不是同计算量方法胜负或新算法准确率**。035-2联合输出组织了一个可由早期两帧支持的向下发展关系，但单帧输出并集已有同向描述；保留为关系组织线索，不计独有新事实。

## 5．具体能力与风险

| 案例 | 直接观察到的现象 | 支持的判断 |
|---|---|---|
| 012-3／386-1 | 灰色胶带、FIRST COMPUTER TOUCHSCREEN在部分输出中正确读出 | 保留局部属性/文字提取能力线索；首次文字是视频陈述，不是独立历史证明 |
| 035-2 | 联合描述向下绘制；没有读出BANKS及下方完整列表，比较组引用过早 | 能给方向描述，不等于完整提取过程及其来源 |
| 103-1 | 联合只反复描述叉子，漏掉垃圾桶；不说明投掷未直接展示 | 对象识别不等于关系完整；不能把先后画面提升为实际投掷证据 |
| 383-2／538-1 | 船只图、商店规则文字说对部分内容，却引用不存在该内容的早期帧 | 图像内容与来源绑定要分别验证；“看过组内某帧”不能替代准确溯源 |
| MLVU Q866 | 单帧2/3描述现金；联合说成信用卡支付 | 多帧并不保证纠正单帧，还可能覆盖已有正确事实 |

| 584-3／MLVU Q624 | 识别仰卧或竖琴，却没有说明局部画面不能确认全片最后动作/总次数 | 局部可见性和全局限定能力没有同时成立 |
| 538-1对照单帧3 | 将提示中的source time写为屏幕文字 | 提示元数据不能当OCR；事实来源需要独立检查 |

## 7．主线更新与下一层边界

继续保留检索定位与精确采样，结束当前固定事实观察器实现。**目前仍没有通过验收的事实/关系信号可用于统一exp07和exp12**；不据本轮生成新覆盖公式，不启动小测/全量。

下一次若继续事实路线，应先单独讨论“来源绑定及观察范围可验证的最小接口”，而不是扩大调用量：例如单帧身份由调用端绑定、模型只转录可见内容，联合关系必须指向已验证事实及正确源帧。但这只是待review的架构方向，本轮未修改提示、解析、输入形式或运行第二版，也未证明该方向能提高最终QA。

本轮完成了能力边界验证，而非答题精度提升。已确认原则不变；工作假设从“直接采用帧组输出可能提供新价值信号”收缩为“局部事实有线索，但格式、溯源、限定和联合增量必须先单独建立可靠性”。
