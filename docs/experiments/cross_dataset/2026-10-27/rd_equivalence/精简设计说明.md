# RD共同选择执行链：职责与等价依据

本页说明同一exp07/exp12如何以更直接的执行链计算。方法ID、冻结问答成绩与上游取证规则不变；本轮不产生新准确率。完整验证结果另见本目录的重放记录。

统一的是执行实现，两版的覆盖目标差异仍保留；本轮没有解决两版在不同配置下优势不一致的算法问题。

## 生产流程

```mermaid
flowchart LR
    A[冻结粗细候选与BLIP-1特征] --> B[核验K对应原计划]
    B --> C[原唯一选择归属与必要区域摘要]
    C --> D[原局部前缀与所选覆盖曲线]
    D --> E[一次原DP]
    E --> F[按源时间排序的唯一帧]
```

接口为`select_rd(pool, features, frame_budget, method_id, trace_mode="summary")`。方法只接受RD-1.2-exp07和RD-1.2-exp12；实现身份为`rd_selection_equivalent_v1`，它是工程实现修订，不是新的方法版本。

后续调用示例：

```python
from videoqa_methods.rd_selection import select_rd

indices, trace = select_rd(pool, features, frame_budget=32,
                           method_id="RD-1.2-exp12")
selection = {"video": pool["video"],
             "selected_frames": [pool["candidates"][i] for i in indices]}
```

`selection`沿用现有后端的输入格式；运行元数据同时保留原方法ID及`trace["implementation_id"]`。历史执行器继续使用其原冻结入口。

输入必须是同一K下已合法构建的池。种子数为`min(K,N_coarse)`，最终实际预算为`min(K,N_eligible)`，两者分别记录。函数不采样、解码、编码、生成或训练。

上游仍按原目标时间连接核心、按真实源PTS扩窗与合并，并执行原条件补查。选择层核验原计划后，只投影区域ID、原边界、种子、锚点与密度权重，再沿用原整数PTS中点切分。完整核心仍保留在原计划及审计中，也会为输入核验而临时重建；本轮去掉的是下游复制和历史对照耦合，没有取消核心计算。

## 局部次序与覆盖

每区先保留原最高分种子锚点，继续按原相关性加权种子支持L与最大已选相似度D，选择`L×sqrt(1−D)`最大的候选。同分沿用真实PTS、候选编号顺序。来源为粗帧还是细帧不参与优先级。

所选方法的覆盖目标在构建前缀时同步递推，参考点仍只有粗帧：

- exp07：粗参考帧等权，覆盖为当前前缀对每个粗参考的最大相似度的均值。
- exp12：粗参考采用区内原问题ITM分数归一化权重；全零回退与等分数精确等价分支沿用原实现，保持原单调截断。

两个方法最后都只调用一次原`allocate_prefix_budget`。每区正配额、区域密度乘数、原DP同分顺序及总预算闭合保持原样。最优性仍仅适用于这些固定前缀与约束，不能解释为任意帧子集或QA准确率的全局最优。

## 被移出的重复工作

| 原执行依赖 | 新执行方式 | 等价理由 |
|---|---|---|
| exp12先得到一份等权DP配额 | 直接以K及合法池大小确定预算，只求加权DP | 旧等权配额之和已由原预算闭合约束确定，等权配额不决定加权DP的候选前缀 |
| exp12再次递推同一前缀的最大参考相似度 | 在原前缀构建的同一递推中计算所选目标 | 操作数、matvec形状、Float32累积、Float64权重/均值与截断顺序保持原定义 |
| 生产输入需要可行参照配额及历史轨迹 | 生产接口不接受这些参数 | 它们仅用于旧目标下界检查或反事实，不决定当前DP的argmax |
| 两次选择单元构建复制完整核心树和统计 | 下游仅复制必要区域摘要 | 原切分函数只消费这些区域字段，核心的触发/解释职责仍留在上游 |

没有把全成员重复度的切片替代粗参考matvec，也没有引入矩阵批量重排、近同分容差或求解器回退，以免改变浮点路径及离散选择。

## 哪些量仍然存在

| 类别 | 保留内容 | 处理原则 |
|---|---|---|
| 唯一公开帧预算 | K | 复用此前已完成的单预算接口，不重复算作本轮成果 |
| 原设计选择 | 2秒连接、±4秒范围、3种子触发、2 FPS网格 | 本轮没有新的行为证据删除它们，实际意义与参数值不变 |
| 上游派生量 | 核心大小、连接数、密度权重、触发依据 | 原构建函数统一产生；`m−c`等于连接数，不维护第二套密度定义 |
| 当前选择量 | 种子支持、重复度、前缀、参考覆盖、配额 | 分别有局部次序或预算职责，完整追踪可导出 |
| 历史审计量 | reference_quotas、旧目标值、旧选择、可行下界 | 由独立审计旧链计算，不进入新生产接口 |

`[3,1]`和`[2,2]`可能密度相同而触发不同；VFR中目标时间相近的种子可能具有较大的真实源时间间隔。因此不把触发改成密度阈值，也不把核心扩窗无条件改成逐种子窗口并集。

## 追踪、使用与验收

摘要包含方法/实现身份、K、实际种子数/帧数、锚点、当前配额及目标值。完整模式另外导出当前区域边界、成员/粗参考、前缀、局部获胜分数和覆盖曲线；它只增加记录，不增加求解。

旧函数和历史执行器继续用于历史复现；后续实验可显式调用新入口并记录实现身份。不能改写旧发布哈希或把相同源帧对应的历史答案写成新测成绩。

独立审计同时核对旧链、新完整/摘要模式和冻结记录：源帧/顺序、前缀、配额等离散量零容差，数值共同量≤1e-6；实际计数确认旧exp12两次DP、新入口每次一次。CPU计时和RSS仅评价执行实现，不表示BLIP或原片E2E提速。

这里“两次到一次”针对从候选池独立求解单个exp12目标的旧链。原四策略实验同时产出exp07和exp12时，等权DP也服务exp07结果；若调用方明确需要两种目标，两次求解仍各有用途。旧联合入口共享前缀，不应把两个单方法计时相加当作其批量成本。本轮保留原联合实验入口，性能结论限定于所测单方法执行链。
