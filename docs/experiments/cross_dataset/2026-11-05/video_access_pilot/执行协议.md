# 受控原片访问可行性试点

## 授权与研究问题

用户确认完整测试探索。本轮检验：共享低成本预览后，原片访问产生的精度收益能否抵偿获取、解码和计算成本，RD是否比强选帧及简单邻接补取更有价值。不是已确认的应用优势，不改写RD冻结公式或登记新的exp版本。

以BLIP-1＋LLaVA8先验证，保留exp12为统一RD参照；不按配置切换父版本。Video-MME首轮未通过投入条件则不接续MLVU，也不自动降低预览质量、修改链路或补查参数。

## 固定条件

- 预览：全片1 FPS、1/4秒相位、真实PTS映射去重；等比例完整画面长边最多320，JPEG80、色度采样2，不放大小图。
- 模型：原BLIP-1 FP32、batch16、TF32关闭，只输入原问题；LLaVA BF16＋SDPA、官方384、qwen_1_5、K8、贪心、16新Token、种子2027。
- 源数据：原Video-MME开发200题按原顺序每时长取前20个不同视频，共60；原MLVU210题每任务前10个不同视频，共70。原开发、预留清单不改，不按对错筛选；两组均为已观察诊断样本。
- 原片服务：回环HTTP、服务端真实解码、统一关键帧批量合并、无损PNG响应，记录逻辑文件读取字节/seek、实际解码帧数、编码和响应体字节。不是远端MP4字节范围成本，也不称物理磁盘冷读。
- 初始预览与完整源PTS索引是共同权限；完整索引只提供身份/时钟。选择不能使用未获取原图的历史分数、视觉特征或细池。粗细视觉表示都使用同一预览规格，原图用于最终QA。
- 原片增量返回预算检查点8/32 MiB；按完整访问记录检查可执行性，超预算即标未完成，不能附用无限预算答案。旧RD没有自动预算停止能力，本轮不擅自截池或增加停采公式。
- 链路：local不附加限制；fast=100 Mbps＋10ms；limited=20 Mbps＋50ms。两限制档为工程假设，全部报告。只重放真实响应体，不重复QA；重放不含解码，解码由原请求单列，不把两者混称独立E2E。

## 六组比较与规模

1. BASE-Uniform：源帧编号均匀K8，获取原图，无BLIP成本。
2. BASE-BLIP-TopK：预览评分Top-8，获取原图。
3. REF-WFS-SB：固定公开核心、默认配置、BLIP-1共同预览、K8，获取原图。不是作者默认前端和公开发布选帧复现。
4. CTRL-WFS-preview：同一WFS选择，只用预览回答。
5. CTRL-TopK-local：初始Top-8每张请求原目标后0.5秒的合法唯一源，按同一预览规格新增ITM后，在粗细全集重取Top-8；额外ITM单列。
6. RD-1.2-exp12：原Top-K种子、核心/扩窗/合并、条件2 FPS补查、纯视觉细特征和原加权覆盖DP。所有实际候选访问计费。

Video-MME最多360真实QA，通过后MLVU最多420；全局780上限，合成最多8。完整同题输入一致才共享，调用计划先于生成冻结，不引用旧清晰原片协议答案。保留提示、源身份、RGB、官方像素、Token、原始返回、调用开始/返回及恢复记录。

共同粗评分只实际计算一次以保证比较输入相同；每个需要检索的方法独立计入其完整费用。共享准备时间不是方法独立E2E。预览创建和初次获取单列，Uniform只需索引元数据，不强制支付JPEG或检索费用。每题每方法原图缓存独立；所有方法享有相同服务、解码、批量与缓存权限。

## 顺序与判断

先完成12个视频（两数据集各6、VME每时长2）的无模型原片服务验收及链路校准，再冻结60题完整输入与唯一调用表，合成及各工作进程前5题按工程正确性放行。CPU/解码各2线程，最多2张实际空闲GPU，后台setsid/nohup，阶段切换、日志、心跳及汇总自动执行。

进入MLVU须：至少一个固定预算和限制链路档中，相对所有可行对照中最高正确数净增≥2/60且字节/时延均不超过对照10%；或正确数不低于所有可行对照且对精度不低于RD的最廉价对照，时延或字节至少下降20%、另一项不增加。不能只与Uniform比较。所有条件和未完成率均报告；预算不足的题不进入成功答案，主分母保持60。该门槛只指导投入，不是显著性/等价证明。

若没有可比较的预算可行点，或仍被强基线精度与成本共同支配，结束本试点。主报告保留无限预算诊断与预算可执行率，配对区间按视频bootstrap10000次/2027；MLVU另报原生和单字母句点归一化M-Avg。不称独立盲测，不自动启动Qwen32或全量。

未知生成、OOM、输入/指纹变化立即暂停；已启动失败占额度，答错/解析失败不重试，有完整原始返回只恢复后处理。完成恢复须0新模型调用且既有完成结果不变。每阶段验证review后提交，不推送，保留用户已有分析脚本。
